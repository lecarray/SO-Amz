<a id="p0003"></a>
**P0003** 说话人2（宋之老师） 02:51

<a id="p0004"></a>
**P0004** 前面跟大家讲到关于广告活动拆分和合并，从而做放量的问题。如果你的产品活动拆得比较多，但又没有足够预算的话，我个人建议把活动合回去。

<a id="p0005"></a>
**P0005** 一、活动预算的最低标准

<a id="p0006"></a>
**P0006** 一个活动至少要给到 3-5 个 CPA 的预算，这个活动才算有相对合理的预算。

<a id="p0007"></a>
**P0007** 举例：出一单成本 $10 → 这个活动至少给 $30-$50 的预算，才能比较充分地跑数据。

<a id="p0008"></a>
**P0008** 如果本身没有这么多预算：

<a id="p0009"></a>
**P0009** • 先把活动数量减下来（合并活动）；

<a id="p0010"></a>
**P0010** • 合并后如果还经常超预算 → 大概率是竞价给高了；

<a id="p0011"></a>
**P0011** 二、压竞价（讲价）的最佳时机

<a id="p0012"></a>
**P0012** 何时可以压竞价：当活动预算严重不足（经常提前花完）时。

<a id="p0013"></a>
**P0013** 这代表两件事：

<a id="p0014"></a>
**P0014** 1. 亚马逊愿意帮你花这笔钱（表现不错）；

<a id="p0015"></a>
**P0015** 2. 你有资格跟亚马逊"讲价"（要求更低的 CPC）；

<a id="p0016"></a>
**P0016** 反之：如果预算花不完，不要莫名其妙地压竞价 → 大概率导致广告位下降。

<a id="p0017"></a>
**P0017** 三、压竞价的四种方案

<a id="p0018"></a>
**P0018** 方案一：无痛缓压法（最安全）

<a id="p0019"></a>
**P0019** 适用场景：不敢动竞价、稳健型操作

<a id="p0020"></a>
**P0020** 操作步骤：

<a id="p0021"></a>
**P0021** 1. 预算不足时，每天把竞价降 $0.01（如从 $2.0 降到 $1.99）；

<a id="p0022"></a>
**P0022** 2. 持续降，每周降约 $0.07；

<a id="p0023"></a>
**P0023** 3. 直到预算基本能花完为止，停止操作；

<a id="p0024"></a>
**P0024** 优点：广告位不变，花费不变，几乎零风险。

<a id="p0025"></a>
**P0025** 缺点：速度慢。

<a id="p0026"></a>
**P0026** 方案二：小幅快压法（稍快）

<a id="p0027"></a>
**P0027** 适用场景：想快一点但不愿意大幅操作

<a id="p0028"></a>
**P0028** 操作步骤：

<a id="p0029"></a>
**P0029** 1. 初始预算不变（$50）、竞价 $2.0；

<a id="p0030"></a>
**P0030** 2. 当天在原竞价上多加 $10 预算（总 $60）；

<a id="p0031"></a>
**P0031** 3. 把竞价降到 $1.99；

<a id="p0032"></a>
**P0032** 4. 看这 $10 额外预算能否花完；

<a id="p0033"></a>
**P0033** 5. 如果能花完 → 说明 $1.99 也够花 → 继续降到 $1.98，再加 $10；

<a id="p0034"></a>
**P0034** 6. 如果 $10 还没花完 → 继续降到 $1.97 再加 $10；

<a id="p0035"></a>
**P0035** 7. 以此往复，直到加的那 $10 刚好能花完为止，停止操作；

<a id="p0036"></a>
**P0036** 一天可以做多轮，睡前做一轮、起床做一轮即可（注意休息）。

<a id="p0037"></a>
**P0037** 方案三：快速压法（较快）

<a id="p0038"></a>
**P0038** 适用场景：竞价明显偏高、想快速压下来

<a id="p0039"></a>
**P0039** 操作步骤：

<a id="p0040"></a>
**P0040** 1. 初始 $2.0，预算当天很快花完 → 说明可以大幅压；

<a id="p0041"></a>
**P0041** 2. 直接降到 $1.96（一次降多一点）；

<a id="p0042"></a>
**P0042** 3. 加 $10 预算，看能否花完；

<a id="p0043"></a>
**P0043** 4. 能花完 → 继续降 $1.93；

<a id="p0044"></a>
**P0044** 5. 按此节奏，3 天内可以从 $1.2 压到 $0.74（实测案例）；

<a id="p0045"></a>
**P0045** 产品权重越高、原竞价给得越偏高 → 操作可以越快。

<a id="p0046"></a>
**P0046** 方案四：加速省钱版（最高效）

<a id="p0047"></a>
**P0047** 适用场景：想当天完成多轮操作且不花超预算

<a id="p0048"></a>
**P0048** 操作逻辑：把当天总预算分成多份，每份只用来"验证这个竞价够不够花"。

<a id="p0049"></a>
**P0049** 步骤：

<a id="p0050"></a>
**P0050** 1. 初始预算给低（如 $25，而非 $50）；

<a id="p0051"></a>
**P0051** 2. 花完后加第二份（$13），继续测下一个竞价档；

<a id="p0052"></a>
**P0052** 3. 再加 $13，测第三档；

<a id="p0053"></a>
**P0053** 4. 当天总花费约等于 $50，但已经完成了多轮竞价压缩；

<a id="p0054"></a>
**P0054** 5. 每天重复，每次的"初始竞价"以前一天结束的竞价为起点；

<a id="p0055"></a>
**P0055** 每个竞价档之间差距不用太大，压的过程中只要每层级间距不过大，返回上一档都不会有明显影响。

<a id="p0056"></a>
**P0056** 四、只跑 TOS 位置时的压竞价方式

<a id="p0057"></a>
**P0057** 前提：你明确只想跑 TOS 位置（不要其他位置）。

<a id="p0058"></a>
**P0058** 正确做法：低底价 + 高 TOS 广告位加价。

<a id="p0059"></a>
**P0059** 举例：TOS 竞价应为 $2.0 → 设置底价 $0.5 + TOS 加价 300%：

<a id="p0060"></a>
**P0060** • 实际 TOS 竞价 = $0.5 × (1 + 300%) = $2.0；

<a id="p0061"></a>
**P0061** 压竞价时：底价不动，只调整 TOS 加价百分比。

<a id="p0062"></a>
**P0062** 举例：

<a id="p0063"></a>
**P0063** • 初始：底价 $1.0 + TOS 加价 250%（实际 $3.5）；

<a id="p0064"></a>
**P0064** • 压到：底价 $1.0 + TOS 加价 240%；

<a id="p0065"></a>
**P0065** • 继续压：底价 $1.0 + TOS 加价 230%……直到加价为 190% 时不出曝光，回到 210%；

<a id="p0066"></a>
**P0066** 注意：

<a id="p0067"></a>
**P0067** • 不要执着于卡 TOS 第一位 → 第一第二位都是 TOS，溢价差距很大；

<a id="p0068"></a>
**P0068** • 你的底价如果直接给低（如 $0.05），再加 TOS 加价，也可以正常跑（实测 $0.15 底价 + 750% 加价依然正常）；

<a id="p0069"></a>
**P0069** • 如果不是专门做 TOS 卡位，不需要用这个方式；

<a id="p0070"></a>
**P0070** 五、不同时段的 TOS 位置竞价成本

<a id="p0071"></a>
**P0071** TOS 位置不同时段竞价差异极大。

<a id="p0072"></a>
**P0072** 规律：竞对越少的时段，TOS 竞价越便宜。

<a id="p0073"></a>
**P0073** 观察方法（西柚广告放映机）：

<a id="p0074"></a>
**P0074** • 记录不同时段各产品在 TOS 的出现情况；

<a id="p0075"></a>
**P0075** • 发现多数卖家会在某个时间点"离场"（预算花完）；

<a id="p0076"></a>
**P0076** • 离场后，原来排在后面的产品会自动前移；

<a id="p0077"></a>
**P0077** 案例规律：

<a id="p0078"></a>
**P0078** • 早高峰（0:00 ~ 8:00）：竞对最多，TOS 竞价最贵；

<a id="p0079"></a>
**P0079** • 下午 2:00 ~ 6:00：竞对陆续离场，竞价开始下降；

<a id="p0080"></a>
**P0080** • 晚上 6:00 ~ 10:00：出单高峰，但竞对已没预算，竞价极便宜；

<a id="p0081"></a>
**P0081** 策略应用：

<a id="p0082"></a>
**P0082** • 不追求卡位的卖家 → 给一个中等竞价，不管广告位，等后半段低价花完预算；

<a id="p0083"></a>
**P0083** • 举例：正常 TOS 高峰期 $3.0，我给 $2.0，早上可能在第二页，下午竞对陆续走后，晚上就能升到第一页第五位甚至更高；

<a id="p0084"></a>
**P0084** • 这种"等着捡"的方式，适合腰部产品；

<a id="p0085"></a>
**P0085** 六、广告拍卖机制：Ad Rank 与 CPC 的关系

<a id="p0086"></a>
**P0086** （一）广告拍卖三个环节

<a id="p0087"></a>
**P0087** 1. **分发机制**：买家搜索词 → 系统遍历所有能触发该词的投放词；

<a id="p0088"></a>
**P0088** 2. **排序机制**：无效广告（暂停/超预算/存档/无库存）被移除 → 按 Ad Rank 排序；

<a id="p0089"></a>
**P0089** 3. **竞价机制**：广告被点击后扣费（CPC）；

<a id="p0090"></a>
**P0090** 重要：暂停的广告 = 超出预算的广告 = 存档的广告，在排序阶段都是无效的，不影响竞品的实际排序竞价。

<a id="p0091"></a>
**P0091** 所以：暂停的活动不会影响别人，也不会"降权重"（权重不变），直接暂停即可，不需要设预算为 $1。

<a id="p0092"></a>
**P0092** （二）Ad Rank 公式

<a id="p0093"></a>
**P0093** Ad Rank = Bid（出价）× Quality Score（质量得分）

<a id="p0094"></a>
**P0094** • Quality Score = 累积权重（+ 广告预期坑产 + 活动权重）；

<a id="p0095"></a>
**P0095** • Ad Rank 越高，广告位越靠前；

<a id="p0096"></a>
**P0096** 举例：三个广告主 A/B/C，出价分别 $2/$3/$4，质量得分分别 10/5/3：

<a id="p0097"></a>
**P0097** | 广告主 | Bid | 质量得分 | Ad Rank |

<a id="p0098"></a>
**P0098** |---|---|---|---|

<a id="p0099"></a>
**P0099** | A | $2 | 10 | 20（第一） |

<a id="p0100"></a>
**P0100** | B | $3 | 5 | 15（第二） |

<a id="p0101"></a>
**P0101** | C | $4 | 3 | 12（第三） |

<a id="p0102"></a>
**P0102** → 出价最低的 A 拿到第一广告位。

<a id="p0103"></a>
**P0103** 结论：Bid 高不等于广告位好；质量得分高 → 同竞价下广告位更好 + 实际 CPC 更低。

<a id="p0104"></a>
**P0104** （三）CPC 计算公式

<a id="p0105"></a>
**P0105** 实际 CPC = 下一位 Ad Rank ÷ 你的质量得分 + $0.01

<a id="p0106"></a>
**P0106** 举例：A（Ad Rank=20，质量得分=10），B 的 Ad Rank=15：

<a id="p0107"></a>
**P0107** • A 的 CPC = 15 ÷ 10 + 0.01 = $1.51

<a id="p0108"></a>
**P0108** 结论：

<a id="p0109"></a>
**P0109** 1. **Bid 必定大于 CPC**（Bid 是出价，CPC 是实际扣费，扣费必定比出价小）；

<a id="p0110"></a>
**P0110** 2. 如果实际 CPC 远小于 Bid → 说明竞价给高了，有压价空间；

<a id="p0111"></a>
**P0111** 3. 如果出现 CPC > Bid 的情况 → 一定是广告位加价/分时竞价/ERP 自动调价等设置导致实际 Bid 被抬高了；

<a id="p0112"></a>
**P0112** （四）关于暂停 vs 设预算为 $1

<a id="p0113"></a>
**P0113** • 推荐暂停，不推荐设预算为 $1；

<a id="p0114"></a>
**P0114** • 原因：设为 $1 的活动会影响对广告预算情况的判断（超预算分析会出现干扰）；

<a id="p0115"></a>
**P0115** • 实测：暂停两年的老活动重新启用，依然有活动权重，效果正常；

<a id="p0116"></a>
**P0116** 七、同账户下重复投放的规律与竞价架构

<a id="p0117"></a>
**P0117** （一）基本规律

<a id="p0118"></a>
**P0118** 在同一个账户下，同一个搜索词会触发多个投放词（广泛/词组/精准/Auto 等）。

<a id="p0119"></a>
**P0119** 重复投放无法完全避免（除非只投精准 + Auto，且 Auto 中对精准词做否定）。

<a id="p0120"></a>
**P0120** 但：可以控制重复投放不产生"内卷"（自己互相抬价）。

<a id="p0121"></a>
**P0121** （二）范围越小的投放需要越高的竞价

<a id="p0122"></a>
**P0122** 关键原理：

<a id="p0123"></a>
**P0123** 广泛（大打包）先开 → 后开的精准/二级词（小打包）要抢它的曝光，必须给更高竞价才能排在前面。

<a id="p0124"></a>
**P0124** 类比：

<a id="p0125"></a>
**P0125** • 大打包 = 大猪圈（100 人间）；

<a id="p0126"></a>
**P0126** • 小打包 = 小猪圈（50 人间）；

<a id="p0127"></a>
**P0127** • 你给小打包开了个小猪圈，但搜索词进来后先遇到大猪圈 → 还是进大猪圈了；

<a id="p0128"></a>
**P0128** • 要让搜索词进小猪圈，小猪圈的竞价得比大猪圈高；

<a id="p0129"></a>
**P0129** 竞价层级原则：精准 > 广泛（≥词组）> Auto > 商品投放

<a id="p0130"></a>
**P0130** 具体建议：

<a id="p0131"></a>
**P0131** • 二级词广泛：竞价比一级词广泛高 10%~20%（如一级词 $2.0 → 二级词 $2.2）；

<a id="p0132"></a>
**P0132** • 精准：竞价 ≥ 广泛；

<a id="p0133"></a>
**P0133** • Auto：竞价比一级词广泛低（如 $1.8）；

<a id="p0134"></a>
**P0134** • 商品投放：最高不超过广泛/Auto，通常小于 Auto；

<a id="p0135"></a>
**P0135** （三）实际效果：有差别竞价 vs 无差别竞价

<a id="p0136"></a>
**P0136** | 类型 | 曝光分布 |

<a id="p0137"></a>
**P0137** |---|---|

<a id="p0138"></a>
**P0138** | 无差别竞价（都一样） | 大打包吃大头，小打包吃小头，数据乱成一团 |

<a id="p0139"></a>
**P0139** | 有差别竞价（小范围更高价） | 小打包曝光量更多，呈现清晰的流量层级 |

<a id="p0140"></a>
**P0140** 案例（游戏耳机）：

<a id="p0141"></a>
**P0141** 第一周：只投一级词广泛 → 花费 $1,600，曝光 96,000，CPC $1.05；

<a id="p0142"></a>
**P0142** 第二周：增加二级词广泛（标红词），竞价略高 → 花费 $2,700，曝光 170,000，CPC $1.09；

<a id="p0143"></a>
**P0143** 花费翻倍，CPC 几乎不变，曝光量大幅提升 → 有效放量。

<a id="p0144"></a>
**P0144** 八、广告结构全景：一级/二级/三级词的放量架构

<a id="p0145"></a>
**P0145** （一）广告放量结构的四个层次

<a id="p0146"></a>
**P0146** ```

<a id="p0147"></a>
**P0147** Auto（范围最大，竞价最低）

<a id="p0148"></a>
**P0148** ↓

<a id="p0149"></a>
**P0149** 一级词广泛（定向大范围广撒网）

<a id="p0150"></a>
**P0150** ↓

<a id="p0151"></a>
**P0151** 二级词广泛（小打包，竞价略高于一级）

<a id="p0152"></a>
**P0152** ↓

<a id="p0153"></a>
**P0153** 精准词（单词单组，竞价最高）

<a id="p0154"></a>
**P0154** ```

<a id="p0155"></a>
**P0155** 商品投放（PT）：与以上并行，竞价 ≤ Auto 或广泛

<a id="p0156"></a>
**P0156** （二）Auto 的正确角色

<a id="p0157"></a>
**P0157** • Auto = 范围最大的大打包；

<a id="p0158"></a>
**P0158** • 适合做收录和初步测试；

<a id="p0159"></a>
**P0159** • 竞价要给所有层级中最低的；

<a id="p0160"></a>
**P0160** • 不要让 Auto 竞价高于一级词，否则后面所有层级都会被 Auto 压制；

<a id="p0161"></a>
**P0161** 典型错误：Auto 给 $1.2 → 广泛 $1.5 → 但广泛开出来还是被 Auto 抢走曝光，不得不继续加竞价 → 恶性循环。

<a id="p0162"></a>
**P0162** （三）一级词广泛的作用

<a id="p0163"></a>
**P0163** • 定向广撒网，比 Auto 更准确；

<a id="p0164"></a>
**P0164** • 每个词根开一个一级词活动（分开活动）；

<a id="p0165"></a>
**P0165** • 目的：测试 + 收录 + 初步放量；

<a id="p0166"></a>
**P0166** （四）二级词广泛的作用

<a id="p0167"></a>
**P0167** • 把一级打包里面的小打包拆出来，单独放量；

<a id="p0168"></a>
**P0168** • 二级词 = 一级词 + 一个词根；

<a id="p0169"></a>
**P0169** • 竞价比一级词高 10%~20%；

<a id="p0170"></a>
**P0170** • 每个二级打包单独一个活动；

<a id="p0171"></a>
**P0171** • 效果：被一级词压制的长尾词获得充分曝光；

<a id="p0172"></a>
**P0172** 举例（showerhead 产品）：

<a id="p0173"></a>
**P0173** • 一级词：showerhead（广泛，覆盖 5,000 个词，250 万搜索量）；

<a id="p0174"></a>
**P0174** • 二级词 A：showerhead handheld（广泛，覆盖 693 个词，44 万）；

<a id="p0175"></a>
**P0175** • 二级词 B：showerhead high pressure（广泛，61 万）；

<a id="p0176"></a>
**P0176** • 二级词 C：showerhead filter（广泛，14 万，370 个词）；

<a id="p0177"></a>
**P0177** • 这几个二级词打包独立开活动，给比一级词高的竞价；

<a id="p0178"></a>
**P0178** 一旦放开二级词，花费往往能直接翻倍。

<a id="p0179"></a>
**P0179** （五）什么时候需要三级词？

<a id="p0180"></a>
**P0180** • 二级打包体量还是很大（如 44 万）→ 才需要继续拆三级；

<a id="p0181"></a>
**P0181** • 多数产品放到二级已经没有预算了，不需要强求三级；

<a id="p0182"></a>
**P0182** • 三级词需要给更高竞价，会拉高整体竞价水平，谨慎使用；

<a id="p0183"></a>
**P0183** 九、捡漏广告（瀑布流）的设计

<a id="p0184"></a>
**P0184** （一）什么是捡漏广告？

<a id="p0185"></a>
**P0185** 捡漏广告 = 不影响主框架的广告，专门去接那些没被主框架接到的流量。

<a id="p0186"></a>
**P0186** 特征：

<a id="p0187"></a>
**P0187** 1. 竞价比主框架的最低竞价还低；

<a id="p0188"></a>
**P0188** 2. 不影响主框架里的任何活动；

<a id="p0189"></a>
**P0189** 3. 能真的接到漏下来的流量（竞价得够用）；

<a id="p0190"></a>
**P0190** （二）如何设计捡漏广告？

<a id="p0191"></a>
**P0191** 以主框架最低竞价为基准，往下叠加：

<a id="p0192"></a>
**P0192** 举例（主框架最低竞价 $1.8）：

<a id="p0193"></a>
**P0193** • 捡漏层 1：Auto，竞价 $1.6；

<a id="p0194"></a>
**P0194** • 捡漏层 2：Auto，竞价 $1.5；

<a id="p0195"></a>
**P0195** • 捡漏层 3：Auto，竞价 $1.4；

<a id="p0196"></a>
**P0196** 这三层捡漏都不影响主框架，只是在竞价拍卖结束后接那些"滑落"下来的流量。

<a id="p0197"></a>
**P0197** 捡漏广告的反面：

<a id="p0198"></a>
**P0198** • 开一个 Auto 给 $0.1 → 对方正常竞价已经 $2.0，你的 $0.1 什么都接不到 → 纯心理安慰；

<a id="p0199"></a>
**P0199** • 捡漏要贴着可以接到的最低竞价去给，不是越低越好；

<a id="p0200"></a>
**P0200** 正确的捡漏广告 ≠ 一堆同竞价的重复精准活动

<a id="p0201"></a>
**P0201** 反面案例：某卖家把同一个词开了 5 个活动，竞价从 $0.8 → $0.78 → $1.18 → $1.38 → $1.18（越开越高），导致自己把自己的竞价抬上去了。

<a id="p0202"></a>
**P0202** 正确做法：先开竞价高的（主力），再往下叠竞价低的（捡漏），顺序不能反。

<a id="p0203"></a>
**P0203** （三）捡漏广告的典型案例

<a id="p0204"></a>
**P0204** 某产品的广告架构（正面案例）：

<a id="p0205"></a>
**P0205** • 主力层：精准 $1.33（吃大头）；

<a id="p0206"></a>
**P0206** • 捡漏层：广泛 $1.27、$1.21；

<a id="p0207"></a>
**P0207** • 再往下：精准 $1.12、$1.15（继续捡漏）；

<a id="p0208"></a>
**P0208** 花费呈现漏斗形态：主力 $6,200，次层 $510，捡漏层各 $100 左右。

<a id="p0209"></a>
**P0209** 结论：捡漏广告让你在不抬竞价的情况下花出更多预算，且 CPA 不增加。

<a id="p0210"></a>
**P0210** 十、常见的错误广告架构（反面案例）

<a id="p0211"></a>
**P0211** 反面案例一：Auto 竞价高于其他层级

<a id="p0212"></a>
**P0212** • Auto $0.99 → 精准 $0.84 → 广泛 $0.7 → 词组 $0.49；

<a id="p0213"></a>
**P0213** • Auto 把所有流量都接走了，精准/广泛/词组接不到任何东西；

<a id="p0214"></a>
**P0214** • 解决方案：

<a id="p0215"></a>
**P0215** • 方案一：把精准/广泛/词组竞价抬到 $1.0 以上；

<a id="p0216"></a>
**P0216** • 方案二：把 Auto 竞价压到 $0.7 以下；

<a id="p0217"></a>
**P0217** 反面案例二：同词开多个相同竞价精准

<a id="p0218"></a>
**P0218** • 0.81 → 0.78 → 1.18 → 1.38 → 1.18（越开越高）；

<a id="p0219"></a>
**P0219** • 实质：自己把自己的竞价抬上去；

<a id="p0220"></a>
**P0220** • 解决方案：只保留竞价最高的那个活动，其余关掉；

<a id="p0221"></a>
**P0221** 反面案例三：广泛竞价高于精准

<a id="p0222"></a>
**P0222** • 产品给了"提高降低（Dynamic Bids）"策略 → 提价时广泛的 TOS 实际竞价超过了精准；

<a id="p0223"></a>
**P0223** • 导致精准沦为"捡漏广告"，表现差；

<a id="p0224"></a>
**P0224** • 解决方案：检查竞价策略，确保精准实际竞价 > 广泛实际竞价；

<a id="p0225"></a>
**P0225** 注意：广告层级中的"实际竞价"= 底价 × (1 + 竞价策略加价) × (1 + 广告位加价)

<a id="p0226"></a>
**P0226** 只要其中一项设置有问题，实际竞价就可能乱序。

<a id="p0227"></a>
**P0227** 反面案例四：Auto 跑大头 + 精准捡漏

<a id="p0228"></a>
**P0228** • 所有花费集中在 Auto，精准/广泛都在捡漏；

<a id="p0229"></a>
**P0229** • 原因：Auto 权重积累久了，竞价抬高，后面的层级给不够了；

<a id="p0230"></a>
**P0230** • 解决方案：重建架构，先把 Auto 竞价压下来，再重新给其他层级合理竞价；

<a id="p0231"></a>
**P0231** 十一、广告架构的检查方法

<a id="p0232"></a>
**P0232** 方法：出单词库 → 花费排倒序 → 点小眼睛

<a id="p0233"></a>
**P0233** 操作步骤（领星 ERP）：

<a id="p0234"></a>
**P0234** 1. 广告 → 出单词库 → 花费倒序排列；

<a id="p0235"></a>
**P0235** 2. 点击高花费搜索词旁边的小眼睛；

<a id="p0236"></a>
**P0236** 3. 查看这个词被哪些投放词触发，各自的竞价和花费；

<a id="p0237"></a>
**P0237** 正常的竞价层级应该是这样的：

<a id="p0238"></a>
**P0238** • 精准竞价最高 → 吃大头花费；

<a id="p0239"></a>
**P0239** • 广泛/词组次之 → 吃中等花费；

<a id="p0240"></a>
**P0240** • Auto/商品投放最低 → 捡漏；

<a id="p0241"></a>
**P0241** • 如果某二级词竞价比一级词高 → 二级词吃大头（符合预期）；

<a id="p0242"></a>
**P0242** 异常信号：

<a id="p0243"></a>
**P0243** • Auto 花大头 → 架构问题；

<a id="p0244"></a>
**P0244** • 广泛比精准花得多 → 竞价乱序；

<a id="p0245"></a>
**P0245** • 多个相同范围投放花费相差不大 → 正在互相抢（重复投放没分层）；

<a id="p0246"></a>
**P0246** 方法：透视表（无 ERP 时）

<a id="p0247"></a>
**P0247** 1. 后台下载 SP 搜索词报表（最近 65 天，每日）；

<a id="p0248"></a>
**P0248** 2. 复制粘贴到透视表模板；

<a id="p0249"></a>
**P0249** 3. 刷新透视表 → 搜索词层级按花费倒序；

<a id="p0250"></a>
**P0250** 4. 点开高花费词 → 看对应的投放词和活动；

<a id="p0251"></a>
**P0251** 十二、提高降低竞价策略的注意事项

<a id="p0252"></a>
**P0252** 谨慎使用"提高降低（Dynamic Bids）"竞价策略。

<a id="p0253"></a>
**P0253** 原因：提高时，系统可能把你的实际 TOS 竞价抬到 2 倍，导致：

<a id="p0254"></a>
**P0254** • 你以为底价是 $1.5，但 TOS 实际竞价是 $3.0；

<a id="p0255"></a>
**P0255** • 下面层级的竞价设置被完全覆盖；

<a id="p0256"></a>
**P0256** • 后续不得不给所有层级都加竞价 → 恶性循环；

<a id="p0257"></a>
**P0257** 建议：

<a id="p0258"></a>
**P0258** • 如果要用提高降低，加价幅度不要超过 0.9（即 90% 以内）；

<a id="p0259"></a>
**P0259** • 0.9 以内的提价不会超过下一层级竞价；

<a id="p0260"></a>
**P0260** • 超过 1.0（100%）就开始影响层级架构，越大影响越严重；
