<a id="p0005"></a>
**P0005** 一、盈利型广告的放量方向

<a id="p0006"></a>
**P0006** （一）提升盈利型广告利润的两个要点

<a id="p0007"></a>
**P0007** 盈利型广告利润 = (毛利 − CPA) × 广告单量

<a id="p0008"></a>
**P0008** 提升盈利型广告利润的途径只有两个：

<a id="p0009"></a>
**P0009** 1. **提高毛利和 CPA 之间的差值**（即压低 CPA）；

<a id="p0010"></a>
**P0010** 2. **提高盈利型广告的单量**（即放量）；

<a id="p0011"></a>
**P0011** （二）推广洞察表中找盈利型广告

<a id="p0012"></a>
**P0012** 以某产品定价毛利 $15 为例：

<a id="p0013"></a>
**P0013** • CPA = $14（接近毛利但略低）→ 这是盈利型广告，但出一单利润极薄；

<a id="p0014"></a>
**P0014** • 操作方向：先压低 CPA，再放量；

<a id="p0015"></a>
**P0015** 如何压低 CPA？

<a id="p0016"></a>
**P0016** 判断 CPA 为何偏高：

<a id="p0017"></a>
**P0017** • CVR 是否还有提升空间？若 CVR 已经偏高，无法再上涨；

<a id="p0018"></a>
**P0018** • CPC 是否有压低空间？若市调显示产品竞价范围 $2.6 ~ $4.9，而当前 CPC 还在高档 → 可以下压；

<a id="p0019"></a>
**P0019** 在推广洞察表中为每个词写下预期方向（"许愿"）：

<a id="p0020"></a>
**P0020** • 盈利型词 → 标颜色 + 备注"压低 CPA 并放量"；

<a id="p0021"></a>
**P0021** • 投资型亏损词 → 备注"降低 CPA 或降低花费"；

<a id="p0022"></a>
**P0022** • 明确方向后，后续操作才有依据；

<a id="p0023"></a>
**P0023** 二、投资型广告的放量/缩量方向

<a id="p0024"></a>
**P0024** （一）投资型广告带来的利润来源

<a id="p0025"></a>
**P0025** 投资型广告的利润来自它拉动的自然单利润（而非广告单本身）。

<a id="p0026"></a>
**P0026** 实现方式有两种：

<a id="p0027"></a>
**P0027** 1. **做预期坑产**：让广告亏损，但用亏损换自然位上升；

<a id="p0028"></a>
**P0028** 2. **做实际坑产**：接受广告亏损，靠广告增加总单量，进而带动自然位；

<a id="p0029"></a>
**P0029** （二）投资型广告可以增量的条件

<a id="p0030"></a>
**P0030** 符合以下全部条件时，才考虑给投资型广告增量：

<a id="p0031"></a>
**P0031** 1. **这个词有投资价值**：

<a id="p0032"></a>
**P0032** • 词本身有足够的搜索量；

<a id="p0033"></a>
**P0033** • 当前自然坑位不在前 4（前 4 已无增长空间，此时广告数据不如自然流数据大，主要由自然流表现决定）；

<a id="p0034"></a>
**P0034** 2. **是正向干预**：CVR/CTR 表现要达标（判断方法见前面体检部分）；

<a id="p0035"></a>
**P0035** 3. **干预单量足够**：

<a id="p0036"></a>
**P0036** • 把推广洞察表里的"广告单量"与准词表里的 CPR 数值对照；

<a id="p0037"></a>
**P0037** • CPR 是 8 天的数值 → 推广洞察表里通常拉的是 30 天数据 → 30 天单量 ÷ 4 = 8 天等值，再与 CPR 比对；

<a id="p0038"></a>
**P0038** • 若广告单量 < CPR 对应的干预量 → 单量不足 → 需要补量；

<a id="p0039"></a>
**P0039** 4. **未到瓶颈位**：

<a id="p0040"></a>
**P0040** • 若自然位已在前 10（理想坑位），则不需要再投资推了；

<a id="p0041"></a>
**P0041** • 判断坑位上限的简单方式：看上次做活动（7DD/LD/BD 等）时，这个词的自然位涨到了哪里 → 那就是你的坑位上限。如果活动时都到不了有效位置，说明这个词无法推上去；

<a id="p0042"></a>
**P0042** 5. **自然坑位上限是有效坑位**（参考积木查询的目标排位建议）；

<a id="p0043"></a>
**P0043** （三）投资型广告的缩量时机

<a id="p0044"></a>
**P0044** 出现以下情况时，考虑缩量：

<a id="p0045"></a>
**P0045** • 词的投资价值低：搜索量太小、自然位已在前 4；

<a id="p0046"></a>
**P0046** • 反向干预：CTR 过低（如 6%）→ 广告买的是差数据 → 越打自然位越差；

<a id="p0047"></a>
**P0047** • CTR 6% 对应 CPA 往往也很高（如 $57），这种词坚决缩量；

<a id="p0048"></a>
**P0048** • CTR 12% 也不合格，也要往回撤；

<a id="p0049"></a>
**P0049** • 干预单量不充足且无预算补量；

<a id="p0050"></a>
**P0050** • 已到瓶颈位；

<a id="p0051"></a>
**P0051** • 已达理想坑位（前 4-10 位），可以转成盈利型/平本型广告或直接缩量；

<a id="p0052"></a>
**P0052** （四）推广洞察表 = 推广地图

<a id="p0053"></a>
**P0053** 类比：把推广洞察表当成攻城略地的地图

<a id="p0054"></a>
**P0054** • 搜索量 = 城市面积；

<a id="p0055"></a>
**P0055** • 广告花费 = 派出的兵力；

<a id="p0056"></a>
**P0056** • 自然位高位 = 已攻下的城市；

<a id="p0057"></a>
**P0057** • 守城所需兵力 < 攻城所需兵力 → 攻下来的词可以往回撤花费；

<a id="p0058"></a>
**P0058** 操作原则：

<a id="p0059"></a>
**P0059** • TACoS 没花满 → 找新词花；

<a id="p0060"></a>
**P0060** • TACoS 花满了 → 从已攻下的词（已到高位）里抠出兵力，支援还没打出来的词；

<a id="p0061"></a>
**P0061** • 避免在小搜索量的词上花过多兵力；

<a id="p0062"></a>
**P0062** 三、广告放量的六种方式

<a id="p0063"></a>
**P0063** 以下方式均不需要加竞价就能让广告多花钱：

<a id="p0064"></a>
**P0064** 1. **活动拆分**（本节重点）；

<a id="p0065"></a>
**P0065** 2. 投放词增加；

<a id="p0066"></a>
**P0066** 3. 投放商品增加（ASIN 投放扩展）；

<a id="p0067"></a>
**P0067** 4. 广告位放量；

<a id="p0068"></a>
**P0068** 5. 广告类型放量（从 SP 扩展到 SB/SBV/SD）；

<a id="p0069"></a>
**P0069** 6. 多变体放量；

<a id="p0070"></a>
**P0070** 核心观念：加竞价是放量的最后手段，应优先用上述方式。

<a id="p0071"></a>
**P0071** 广告结构设计原则：

<a id="p0072"></a>
**P0072** • 一个产品理想的广告结构，其理论花费上限应是目标花费的 2 倍；

<a id="p0073"></a>
**P0073** • 比如目标花费 $800/天 → 广告结构理论上能花到 $1,600 → 才有选择和缩减的空间；

<a id="p0074"></a>
**P0074** • 广告结构花费空间不够 → 没有好词可以替换差词，烂广告关不了；

<a id="p0075"></a>
**P0075** 四、广告活动拆分：底层逻辑

<a id="p0076"></a>
**P0076** （一）为什么同一活动里小词发不出去？

<a id="p0077"></a>
**P0077** 广告被触发的流程：

<a id="p0078"></a>
**P0078** 1. 买家搜索某词；

<a id="p0079"></a>
**P0079** 2. 系统遍历所有能触发该词的投放词（AB 广泛、ABC 广泛、ABC 精准、Auto 等都会被触发）；

<a id="p0080"></a>
**P0080** 3. 广告排序 → 出现；

<a id="p0081"></a>
**P0081** 核心规律：曝光量与搜索量正相关

<a id="p0082"></a>
**P0082** • 大词搜索量大 → 曝光量大；

<a id="p0083"></a>
**P0083** • 小词搜索量小 → 曝光量小；

<a id="p0084"></a>
**P0084** • 且亚马逊的"触发即曝光"机制（不需要真正露出才算曝光）→ 大词的曝光量比例被进一步放大；

<a id="p0085"></a>
**P0085** （二）同活动内的"大猪小猪效应"

<a id="p0086"></a>
**P0086** 同一个活动内，预算是给到活动层级的，不是给到单个词的。

<a id="p0087"></a>
**P0087** 这导致：

<a id="p0088"></a>
**P0088** • 大词搜索量大 → 更容易把预算花完 → 亚马逊更倾向于把预算给大词；

<a id="p0089"></a>
**P0089** • 小词被压缩 → 甚至可能一个月只曝光几十次；

<a id="p0090"></a>
**P0090** 类比：大词 = 大猪，小词 = 小猪，都关在同一个猪圈里喂一份食物 → 大猪吃饱，小猪挨饿。

<a id="p0091"></a>
**P0091** （三）轮播机制

<a id="p0092"></a>
**P0092** 广告活动的轮播机制：

<a id="p0093"></a>
**P0093** 同一个活动里词越多，每个词被"轮播"到的频率越低。

<a id="p0094"></a>
**P0094** 具体表现：买家搜 10 次某词，你的广告可能只出现 1 次 → 这就是轮播。

<a id="p0095"></a>
**P0095** 验证方式：在亚马逊前台搜同一个大词，连续搜 3-5 次，会发现广告结果每次都不同（不同品牌出现在不同位置） → 这就是轮播的直观体现。

<a id="p0096"></a>
**P0096** 轮播的影响：

<a id="p0097"></a>
**P0097** • 广告位给够了竞价，但因活动拥挤，每次搜索能出现的概率低；

<a id="p0098"></a>
**P0098** • 活动越拥挤 → 小词的轮播次数越少 → 越发不出去；

<a id="p0099"></a>
**P0099** （四）反面案例：3,000 词堆在同一活动

<a id="p0100"></a>
**P0100** 某卖家的精准广告：把所有出单词全往一个精准活动堆，堆到 3,361 个词。

<a id="p0101"></a>
**P0101** 结果：

<a id="p0102"></a>
**P0102** • 第 1 个词：花费 $268；

<a id="p0103"></a>
**P0103** • 第 2 到 25 个词：合计 $100；

<a id="p0104"></a>
**P0104** • 第 25 个词：一个月只花 $97；

<a id="p0105"></a>
**P0105** • 第 26 个词之后：每月 $4/$3，几乎发不出去；

<a id="p0106"></a>
**P0106** 这就是开了等于没开——只有苦劳没有功劳。

<a id="p0107"></a>
**P0107** 根本原因：这 3,361 个词中的大词把所有预算花完，小词连轮播机会都没有。

<a id="p0108"></a>
**P0108** （五）同一活动里商品投放也是一样的道理

<a id="p0109"></a>
**P0109** 以商品投放（PT）为例：

<a id="p0110"></a>
**P0110** • 同一活动里投了 156 个 ASIN；

<a id="p0111"></a>
**P0111** • 前 1 个 ASIN 点击次数：114 次；

<a id="p0112"></a>
**P0112** • 下面所有 ASIN 合计：只有几次；

<a id="p0113"></a>
**P0113** 这也是大猪小猪效应。

<a id="p0114"></a>
**P0114** 错误应对方式（反面示范）：

<a id="p0115"></a>
**P0115** • 给小猪加竞价（如从 $0.9 加到 $1.0） → 在同一个圈里给小猪"绑火箭"，大猪还是先吃，没用；

<a id="p0116"></a>
**P0116** • 给大猪降竞价 + 给小猪加竞价 → 不如直接分开活动；

<a id="p0117"></a>
**P0117** 正确方式：拆活动（分开猪圈）。

<a id="p0118"></a>
**P0118** 五、广告活动拆分的实操方法

<a id="p0119"></a>
**P0119** （一）何时需要拆活动？

<a id="p0120"></a>
**P0120** 当一个活动内出现"大词花大头，小词发不出去"的情况时，就需要拆活动。

<a id="p0121"></a>
**P0121** 判断方法：看全词表 + 预判投放范围

<a id="p0122"></a>
**P0122** 在全词表里预判：

<a id="p0123"></a>
**P0123** • 投放某个广泛词后，覆盖的词中是否有大有小？

<a id="p0124"></a>
**P0124** • 若有，小词就必然花不到钱；

<a id="p0125"></a>
**P0125** • 预判时就应该计划好分开活动；

<a id="p0126"></a>
**P0126** 举例（吹尘器）：

<a id="p0127"></a>
**P0127** • "compressed air" 广泛覆盖 15 万搜索量 / 208 个词；

<a id="p0128"></a>
**P0128** • "air duster" 广泛覆盖 18 万；

<a id="p0129"></a>
**P0129** • 这两个词体量相当，可以放在一起（两头大猪放一圈）；

<a id="p0130"></a>
**P0130** • "blower" 对应词群搜索量只有 3-4 万 → 不能和前两个放在一起（小猪被压制）；

<a id="p0131"></a>
**P0131** 规则：同量级词可以放在同一活动；不同量级的必须分开。

<a id="p0132"></a>
**P0132** （二）粗暴拆法（简单快速）

<a id="p0133"></a>
**P0133** 1. 在原活动里找出被压制的小词；

<a id="p0134"></a>
**P0134** 2. 直接关闭这些小词的投放；

<a id="p0135"></a>
**P0135** 3. 新开一个活动，重新投放这些小词；

<a id="p0136"></a>
**P0136** 4. 保持竞价不变；

<a id="p0137"></a>
**P0137** 效果：第二天花费翻两倍（因为词终于有自己的预算空间了）。

<a id="p0138"></a>
**P0138** 补充：如果有老活动壳子（闲置活动），优先用老壳子开，不要新开——因为老活动有更高权重，花费更容易出去。

<a id="p0139"></a>
**P0139** （三）丝滑拆法（保留过渡期）

<a id="p0140"></a>
**P0140** 适用于：不舍得直接关闭，担心花费突然断掉的情况。

<a id="p0141"></a>
**P0141** 步骤：

<a id="p0142"></a>
**P0142** 1. 不关闭原活动里的被压制词；

<a id="p0143"></a>
**P0143** 2. 同时在新活动里也开这些词；

<a id="p0144"></a>
**P0144** 3. 给新活动的竞价略高于原活动（如加 5%-10%）→ 让新活动逐渐"抢过来"曝光；

<a id="p0145"></a>
**P0145** 4. 等新活动的词能稳定花出去钱后，再关闭原活动里的对应词；

<a id="p0146"></a>
**P0146** 5. 将新活动竞价改回原竞价；

<a id="p0147"></a>
**P0147** 丝滑拆法完成周期：最快当天，最多三天。

<a id="p0148"></a>
**P0148** 原则：往外拆的是花费少、表现一般的词；花费多、表现好的词留在原活动（保留原活动权重）。

<a id="p0149"></a>
**P0149** （四）测词型拆活动（养蛊法）

<a id="p0150"></a>
**P0150** 用于在测试阶段批量测词时的分批测试：

<a id="p0151"></a>
**P0151** 1. 把一批词放入同一活动；

<a id="p0152"></a>
**P0152** 2. 跑几天后，找出花费大头（表现好的大词）；

<a id="p0153"></a>
**P0153** 3. 把大头词留在原活动；

<a id="p0154"></a>
**P0154** 4. 把剩余词移入新活动继续测；

<a id="p0155"></a>
**P0155** 5. 新活动里同样找出大头词，剩余词再移出；

<a id="p0156"></a>
**P0156** 6. 如此循环，逐步找到每个词根的最优词；

<a id="p0157"></a>
**P0157** 注意：

<a id="p0158"></a>
**P0158** • 某个词在当前测试中"表现不好"≠ 永远不好；

<a id="p0159"></a>
**P0159** • 不要因为一时不好就把词转到低竞价精准里"永久封印" → 应该让它回到原活动继续跑；

<a id="p0160"></a>
**P0160** • 反面案例：某卖家把 Auto → 广泛 → 精准 → 低竞价精准这样递进，最终小词全部被封印，只有大词在花钱，而大词又有多个活动同时花钱，测词完全失去意义；

<a id="p0161"></a>
**P0161** 六、广告层级结构详解

<a id="p0162"></a>
**P0162** （一）各层级能控制的内容

<a id="p0163"></a>
**P0163** | 层级 | 能控制的内容 |

<a id="p0164"></a>
**P0164** |---|---|

<a id="p0165"></a>
**P0165** | 账号层级 | 总预算上限（一般不设） |

<a id="p0166"></a>
**P0166** | 广告组合层级 | 日期范围内的总预算（可用于精确控 TACoS） |

<a id="p0167"></a>
**P0167** | 活动层级 | 广告类型、投放类型、预算上限、预算规则、竞价策略、广告位加价、活动否定 |

<a id="p0168"></a>
**P0168** | 广告组层级 | 推广商品（变体分组）；主层级竞价（几乎不用）；否定（意义不大） |

<a id="p0169"></a>
**P0169** | 投放层级 | 投放对象、匹配类型、竞价 |

<a id="p0170"></a>
**P0170** | 搜索词层级 | 无法直接控制，只能通过前面各层级间接影响 |

<a id="p0171"></a>
**P0171** （二）活动层级必须分开的情况

<a id="p0172"></a>
**P0172** 以下情况需要强制分活动：

<a id="p0173"></a>
**P0173** 1. **不同广告类型**（SP/SB/SBV/SD 必须分开）；

<a id="p0174"></a>
**P0174** 2. **不同投放类型**（关键词投放和商品投放必须分开，不能同一活动混投）；

<a id="p0175"></a>
**P0175** 3. **希望给不同词设置不同预算上限**；

<a id="p0176"></a>
**P0176** 4. **希望使用不同竞价策略**（只降低 / 提高降低 / 固定）；

<a id="p0177"></a>
**P0177** 5. **希望给不同词设置不同广告位加价**（广告位加价是活动级别，会影响活动内所有词）；

<a id="p0178"></a>
**P0178** 6. **希望用不同的预算规则或 ERP 分时预算**；

<a id="p0179"></a>
**P0179** 7. **活动内词之间预算竞争严重**（小词被大词压制）；

<a id="p0180"></a>
**P0180** （三）广告组层级的意义

<a id="p0181"></a>
**P0181** 广告组层级基本没用，原因：

<a id="p0182"></a>
**P0182** • 组层级无法控制预算（预算给到活动层级）；

<a id="p0183"></a>
**P0183** • 组层级无法解决词间预算竞争问题；

<a id="p0184"></a>
**P0184** • 组层级否定意义不大（活动层级已有否定功能）；

<a id="p0185"></a>
**P0185** 唯一有限用途：

<a id="p0186"></a>
**P0186** • 不同变体放不同组（组层级可以控推广商品）；

<a id="p0187"></a>
**P0187** • 但主推变体一般不需要分组；

<a id="p0188"></a>
**P0188** 结论：一般情况下单活动单组，不做多组。

<a id="p0189"></a>
**P0189** （四）用广告组合控 TACoS

<a id="p0190"></a>
**P0190** 广告组合层级可以设置日期范围内的总预算：

<a id="p0191"></a>
**P0191** 操作方法：

<a id="p0192"></a>
**P0192** 1. 把同一个产品的所有广告活动放到同一个组合；

<a id="p0193"></a>
**P0193** 2. 给这个组合设置总预算（如 $1,000/月）；

<a id="p0194"></a>
**P0194** 3. 当组合内所有活动花费加起来达到 $1,000 时，所有活动自动停止；

<a id="p0195"></a>
**P0195** 4. 这样可以精确控制单产品的 TACoS；

<a id="p0196"></a>
**P0196** 注意：组合预算无法每日自动重置，需要手动修改日期（比较麻烦，但值得做）。

<a id="p0197"></a>
**P0197** 七、广告活动合并：缩量方法

<a id="p0198"></a>
**P0198** （一）合并活动的本质

<a id="p0199"></a>
**P0199** 合并活动 = 把词放回同一个猪圈 → 增加轮播竞争 → 压缩每个词的曝光次数 → 降低总花费

<a id="p0200"></a>
**P0200** 合并活动后：

<a id="p0201"></a>
**P0201** • 广告位不变；

<a id="p0202"></a>
**P0202** • 竞价不变；

<a id="p0203"></a>
**P0203** • 但每个词的曝光次数减少（轮播机制起作用）；

<a id="p0204"></a>
**P0204** • 整体花费下降；

<a id="p0205"></a>
**P0205** 注意：合并活动只是降低总花费，不优化单个词的表现。表现好的词依然好，表现差的词依然差，只是它花的更少了。

<a id="p0206"></a>
**P0206** 类比：把乱东西堆进储物间 → 表面整洁，但内部还没真正整理。

<a id="p0207"></a>
**P0207** （二）合并活动的方法

<a id="p0208"></a>
**P0208** 合并同类活动：

<a id="p0209"></a>
**P0209** • 把相关长尾词的词组活动合并；

<a id="p0210"></a>
**P0210** • 把同类型、体量相近的单词单组合并为多词单组；

<a id="p0211"></a>
**P0211** • 将被压制已久、表现也差的词合并到大活动；

<a id="p0212"></a>
**P0212** （三）合并 vs 拆分的选择逻辑

<a id="p0213"></a>
**P0213** | 目标 | 操作 |

<a id="p0214"></a>
**P0214** |---|---|

<a id="p0215"></a>
**P0215** | 想让某词多花钱 | 拆出来，单独给预算 |

<a id="p0216"></a>
**P0216** | 想让某词少花钱（但不关闭） | 合并进大活动，让大词压制它 |

<a id="p0217"></a>
**P0217** | 想让某词彻底不花钱 | 暂停该投放词 |

<a id="p0218"></a>
**P0218** | 想让整个活动少花钱 | 降预算 / 降竞价 / 合并活动 |

<a id="p0219"></a>
**P0219** 八、广告位的"不可能三角"

<a id="p0220"></a>
**P0220** 广告位存在不可能三角：高位置、长时间、低预算 三者不可兼得。

<a id="p0221"></a>
**P0221** | 组合 | 结果 |

<a id="p0222"></a>
**P0222** |---|---|

<a id="p0223"></a>
**P0223** | 低预算 + 高位置 | 曝光时间极短（如只在凌晨花完预算就消失） |

<a id="p0224"></a>
**P0224** | 低预算 + 长时间 | 必定在低位置 |

<a id="p0225"></a>
**P0225** | 高位置 + 长时间 | 必定需要高预算 |

<a id="p0226"></a>
**P0226** 典型误区：

<a id="p0227"></a>
**P0227** • 设置分时预算 + 高竞价 → 把预算都集中在几小时内花完 → 剩余时间完全不曝光；

<a id="p0228"></a>
**P0228** • 凌晨 0:00 ~ 5:00 曝光（买家都没上网），中午之后消失 → 完全无效时段；

<a id="p0229"></a>
**P0229** 建议：

<a id="p0230"></a>
**P0230** • 不拼高位时，用低位置换长时间曝光；

<a id="p0231"></a>
**P0231** • 分时预算应该集中在买家活跃时段（如 8:00 ~ 14:00），而不是全天拉伸但凌晨就用完；

<a id="p0232"></a>
**P0232** 九、降预算 vs 降竞价的区别

<a id="p0233"></a>
**P0233** 降预算

<a id="p0234"></a>
**P0234** 本质：压缩广告曝光时长，从而降低花费。

<a id="p0235"></a>
**P0235** • 同等竞价下，预算减少 → 每天花完预算的时间提前 → 之后不曝光；

<a id="p0236"></a>
**P0236** • 适用于：想把某个活动整体缩量；

<a id="p0237"></a>
**P0237** 降竞价

<a id="p0238"></a>
**P0238** 本质：降低广告位，从而减少高质量曝光量和点击量，进而降低花费。

<a id="p0239"></a>
**P0239** • 适用于：TOS 卡位型产品想缩量时（把 TOS 加价降低）；

<a id="p0240"></a>
**P0240** • 广告位下移后，CTR 自然降低，花费也随之减少；

<a id="p0241"></a>
**P0241** 合并活动

<a id="p0242"></a>
**P0242** 本质：增加轮播竞争，压缩轮播次数，从而降低花费。

<a id="p0243"></a>
**P0243** • 不改变竞价；

<a id="p0244"></a>
**P0244** • 不改变广告位；

<a id="p0245"></a>
**P0245** • 只通过增加词间竞争降低单个词的曝光次数；

<a id="p0246"></a>
**P0246** 十、预算不足的判断与应对

<a id="p0247"></a>
**P0247** 如何判断活动预算不足？

<a id="p0248"></a>
**P0248** 看后台（或 ERP）的"建议预算"与"实际预算"对比：

<a id="p0249"></a>
**P0249** • 建议预算 >> 实际预算 → 亚马逊在暗示你：你的广告表现不错，我能帮你花更多；

<a id="p0250"></a>
**P0250** • 如果你不加预算，亚马逊只能帮你压缩轮播，但可能压不住 → 导致中午预算花完，下午全天不曝光；

<a id="p0251"></a>
**P0251** 应对方式：

<a id="p0252"></a>
**P0252** 1. **加预算**：如果表现好且 TACoS 有空间；

<a id="p0253"></a>
**P0253** 2. **合并活动**：不想加预算，通过合并压轮播；

<a id="p0254"></a>
**P0254** 3. **降竞价（讲价）**：亚马逊"建议多花"= 暗示你可以降竞价。预算完全花不完时，是**降竞价（讲价）成功率最高的时机**。

<a id="p0255"></a>
**P0255** 注意：预算不足时降竞价 = 广告位初期不变，但随着持续降低，位置会逐步下移。如果不介意位置，可以把位置降下来换更长的曝光时间。

<a id="p0256"></a>
**P0256** TOS 卡位型产品的缩量方式

<a id="p0257"></a>
**P0257** TOS 卡位型产品的识别：

<a id="p0258"></a>
**P0258** • 广告位只出现在 TOS，从未出现在其他位置；

<a id="p0259"></a>
**P0259** • 通常使用"低底价 + 高 TOS 广告位加价"的组合；

<a id="p0260"></a>
**P0260** • 识别方法：如果该词的广告位从来都是 TOS，从未往下移 → 大概率是 TOS 卡位；

<a id="p0261"></a>
**P0261** TOS 卡位型产品缩量方法：

<a id="p0262"></a>
**P0262** • 直接降低 TOS 广告位加价（不降底价）；

<a id="p0263"></a>
**P0263** • 广告位下移 → CTR 降低 → 花费自然减少；

<a id="p0264"></a>
**P0264** • 同时曝光时间不减少（因为低位置排名竞争小，更容易全天曝光）；

<a id="p0265"></a>
**P0265** 十一、活动权重与老壳子的利用

<a id="p0266"></a>
**P0266** 广告活动有其自身的累积权重（老活动比新活动权重高）。

<a id="p0267"></a>
**P0267** 利用原则：

<a id="p0268"></a>
**P0268** • 往外拆活动时，优先使用老壳子（闲置的老活动），不新开；

<a id="p0269"></a>
**P0269** • 测试活动、已闲置的活动 → 沉淀为老壳子；

<a id="p0270"></a>
**P0270** • 后续可以把闲置活动改成新词的活动，直接复用活动权重；

<a id="p0271"></a>
**P0271** 实际积累：

<a id="p0272"></a>
**P0272** • 随着拆分 / 测试 / 缩量操作，会积累大量测试活动和闲置活动；

<a id="p0273"></a>
**P0273** • 这些都是宝贵的老壳子，后续有新词需要测试时直接复用；
