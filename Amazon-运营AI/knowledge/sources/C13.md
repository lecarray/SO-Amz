<a id="p0010"></a>
**P0010** 一、准词表：制作流程完整复习

<a id="p0011"></a>
**P0011** （一）找竞品 ASIN

<a id="p0012"></a>
**P0012** 原则：

<a id="p0013"></a>
**P0013** • 找卖了一段时间、销量相对稳定的竞品，不要找刚起量的新品；

<a id="p0014"></a>
**P0014** • 要么去类目节点扒，要么搜准词找头部竞品；

<a id="p0015"></a>
**P0015** • 收集头部这一排（大概 3-6 个）作为对标竞品；

<a id="p0016"></a>
**P0016** • 放的是子体 ASIN，反查子体能查到父体整体数据，不需要区分；

<a id="p0017"></a>
**P0017** • 第一个位置放自己的 ASIN（或表现最差的，不计入竞品表现得分）；

<a id="p0018"></a>
**P0018** 数量控制：

<a id="p0019"></a>
**P0019** • 最少 3 个竞品；

<a id="p0020"></a>
**P0020** • 找不到够好的就 3 个，硬凑反而影响得分准确性；

<a id="p0021"></a>
**P0021** • 不要超过 6 个；

<a id="p0022"></a>
**P0022** （二）H10 Cerebro 操作步骤

<a id="p0023"></a>
**P0023** 路径：H10 → Find Keyword（找词）→ Cerebro

<a id="p0024"></a>
**P0024** 1. 把自己（或最差竞品）的 ASIN 放第一位，后面跟 3-6 个竞品 ASIN；

<a id="p0025"></a>
**P0025** 2. 搜索后向下滑动查看数据；

<a id="p0026"></a>
**P0026** 3. **先把搜索量排倒序**；

<a id="p0027"></a>
**P0027** 4. 筛选"表现得分"6 分以上，看是否有 10 分词出现（有则说明产品方向没问题）；

<a id="p0028"></a>
**P0028** （三）排查差竞品

<a id="p0029"></a>
**P0029** • 把鼠标放在"相对排名"一列；

<a id="p0030"></a>
**P0030** • 观察有没有哪个竞品 ASIN 在各个词下都排名特别低（加粗的是你自己，不看）；

<a id="p0031"></a>
**P0031** • 如果某个 ASIN 在很多词下都拉低了得分 → 删掉这个 ASIN，重新查；

<a id="p0032"></a>
**P0032** • 如果只是偶发性地拉低某几个词 → 不需要删；

<a id="p0033"></a>
**P0033** （四）导出与纠偏

<a id="p0034"></a>
**P0034** • 检查没问题后，不做得分筛选，直接导出全部词（导出后再筛）；

<a id="p0035"></a>
**P0035** • 导出后将"竞品表现得分"及各竞品 ASIN 的自然位列移到靠前位置；

<a id="p0036"></a>
**P0036** • 确定得分阈值：

<a id="p0037"></a>
**P0037** • 用积木查询大词的"有效自然位"数量：

<a id="p0038"></a>
**P0038** • 有效自然位多（如 183 和 43）→ 可以把 6 分词也纳入准词范围；

<a id="p0039"></a>
**P0039** • 有效自然位少 → 只要 8-10 分词；

<a id="p0040"></a>
**P0040** • 没有积木也没关系：8-10 分一定是准词，这个底线不变；

<a id="p0041"></a>
**P0041** • 筛 4-8 分词，寻找是否有方差大的词被误判：

<a id="p0042"></a>
**P0042** • 某词只有两个竞品自然位很低，导致得分被拉低 → 人工改成 6 分；

<a id="p0043"></a>
**P0043** • 某词有 3 个以上竞品排名不错 → 可以往上拉得分；

<a id="p0044"></a>
**P0044** • 重点排查搜索量大的词，搜索量小的几百的词不用管（会被批量覆盖）；

<a id="p0045"></a>
**P0045** （五）准词表加工

<a id="p0046"></a>
**P0046** 完成上述后，还需对准词表做以下三步加工：

<a id="p0047"></a>
**P0047** 加工 1：加入搜索量占比

<a id="p0048"></a>
**P0048** • 分母是准词的总搜索量，而不是全部词的总搜索量；

<a id="p0049"></a>
**P0049** • 搜索量占比 = 该词搜索量 ÷ 准词总搜索量；

<a id="p0050"></a>
**P0050** • 作用：判断流量离散程度（集中型 / 相对离散型 / 非常离散型）；

<a id="p0051"></a>
**P0051** 案例（男士夏威夷衬衫）：

<a id="p0052"></a>
**P0052** • 准词总搜索量约 25.8 万；

<a id="p0053"></a>
**P0053** • 头部 5 个词合计搜索量占比约 36%；

<a id="p0054"></a>
**P0054** • 判断：相对离散型——有几个偏大的词，但流量不是极度集中；

<a id="p0055"></a>
**P0055** 加工 2：判断准词 / 泛词分布

<a id="p0056"></a>
**P0056** 在表格中按得分分组（透视表或手动）计算各层级词的搜索量比例：

<a id="p0057"></a>
**P0057** 举例（男士夏威夷衬衫）：

<a id="p0058"></a>
**P0058** • 6-10 分（准词）：约 60% 搜索量；

<a id="p0059"></a>
**P0059** • 4 分（偏泛词）：约 30% 搜索量；

<a id="p0060"></a>
**P0060** • 更泛：约 10%；

<a id="p0061"></a>
**P0061** 结论：先推准词（60%），靠准词单量滚动实际坑产拉出泛词（30%），再往后拿四分词。

<a id="p0062"></a>
**P0062** > 如果某类产品直接是泛词占大头，准词只有一点点 → 就得先想办法靠实际坑产把泛词一起拉出来，不是先推准词。

<a id="p0063"></a>
**P0063** 加工 3：导入西柚周搜索量（最准数据）

<a id="p0064"></a>
**P0064** • H10 里的搜索量是月搜索量（预估值），不够准；

<a id="p0065"></a>
**P0065** • 西柚的周搜索量与后台 ABA 一致，最准；

<a id="p0066"></a>
**P0066** • 操作：把准词表里的所有词复制 → 西柚找词 → "关键词批量分析" → 粘贴查询 → 导出 → 用 VLOOKUP 函数导入准词表；

<a id="p0067"></a>
**P0067** • 注意：如果产品是季节性的，此时看到的搜索量可能处于淡季低值，旺季数据需要用 H10 钻石版查历史月份数据；

<a id="p0068"></a>
**P0068** 二、词根表：从准词表提取词根

<a id="p0069"></a>
**P0069** （一）收集步骤

<a id="p0070"></a>
**P0070** 按准词表搜索量从高往低，逐词提取词根：

<a id="p0071"></a>
**P0071** 核心词的判定标准：

<a id="p0072"></a>
**P0072** 1. 搜索结果必须都是同类产品；

<a id="p0073"></a>
**P0073** 2. 不可再缩短（再短就不是这个类目了）；

<a id="p0074"></a>
**P0074** 举例（男士夏威夷衬衫）：

<a id="p0075"></a>
**P0075** • 搜索 "hawaiian shirts for men" → 尝试缩短 → 搜 "hawaiian shirts" → 结果一样（都是男士）→ 可以缩短；

<a id="p0076"></a>
**P0076** • 继续缩短 → 搜 "hawaii" → 结果变杂 → 不能再缩；

<a id="p0077"></a>
**P0077** • 核心词 = "hawaiian shirts"，man/men 归入属性词；

<a id="p0078"></a>
**P0078** • 搜 "beach shirts" → 把 "for man" 去掉 → 还是男性居多 → beach shirts 本身能确定类目 → "beach shirts" 是核心词；

<a id="p0079"></a>
**P0079** • 搜 "shirt" → 结果过于宽泛 → "shirt" 是上位词（不是核心词）；

<a id="p0080"></a>
**P0080** 四类词根：

<a id="p0081"></a>
**P0081** | 类型 | 定义 | 示例（夏威夷衬衫）| 后续操作 |

<a id="p0082"></a>
**P0082** |---|---|---|---|

<a id="p0083"></a>
**P0083** | 核心词 | 不可缩短的最短准确词 | hawaiian shirts、beach shirts、tropical shirts、vacation shirts | 投放 + 覆盖验证 |

<a id="p0084"></a>
**P0084** | 属性词 | 修饰核心词的形容词/限定词 | men、funny、short sleeve、big and tall | 对的埋文案；错的词组否 |

<a id="p0085"></a>
**P0085** | 上位词 | 比核心词更宽泛的词 | hawaii、shirts | 初期精准否；成熟期低竞价投放拓泛词 |

<a id="p0086"></a>
**P0086** | 错词根（否定词） | 不是你产品的词根 | woman、kids、boy、halloween | 词组否定 |

<a id="p0087"></a>
**P0087** 注意：

<a id="p0088"></a>
**P0088** • big（大码）和 tall（高个）分开收集，因为它们可以各自覆盖不同的二级词；

<a id="p0089"></a>
**P0089** • 不确定是否是错词的属性词 → 先不投不否，看实际数据再决定；

<a id="p0090"></a>
**P0090** （二）词根表的 AI 辅助整理

<a id="p0091"></a>
**P0091** 手动收集好核心词后，可以把准词表交给 AI（Claude/GPT）辅助分类属性词等。

<a id="p0092"></a>
**P0092** AI 配置指令后续会发给大家；核心词务必自己手动确认，其余让 AI 分类即可。

<a id="p0093"></a>
**P0093** （三）覆盖验证

<a id="p0094"></a>
**P0094** 将收集好的核心词逐个放入全词表做广泛匹配预判（同时包含所有关键词模式），搜完后标颜色。

<a id="p0095"></a>
**P0095** • 全部标完后清除筛选 → 白底的词 = 没被任何核心词覆盖的词；

<a id="p0096"></a>
**P0096** • 这些白底词里 → 找新的核心词补充进来；

<a id="p0097"></a>
**P0097** • 一直循环，直到白底词越来越少为止；

<a id="p0098"></a>
**P0098** 注意：

<a id="p0099"></a>
**P0099** • 搜索时要去掉单复数 s（不然搜不到单数形式）；

<a id="p0100"></a>
**P0100** • 一些非常小的词根（搜索量极小）可以选择不收集，因为初期投放用不到；

<a id="p0101"></a>
**P0101** 三、全词表

<a id="p0102"></a>
**P0102** 制作方法

<a id="p0103"></a>
**P0103** • 把准词表创建一个副本；

<a id="p0104"></a>
**P0104** • 副本不做任何得分筛选，不要搜索量占比列；

<a id="p0105"></a>
**P0105** • 命名为"全词表"；

<a id="p0106"></a>
**P0106** 用途

<a id="p0107"></a>
**P0107** 全词表的核心用途：投放预判 + 提前否词根。

<a id="p0108"></a>
**P0108** 投放预判操作：

<a id="p0109"></a>
**P0109** 1. 在全词表搜索框输入拟投放词（去掉复数/介词/终止词）；

<a id="p0110"></a>
**P0110** 2. 选"同时包含所有关键词"（= 广泛匹配预判）；

<a id="p0111"></a>
**P0111** 3. 查看触发范围内是否有低分词（= 错词根）；

<a id="p0112"></a>
**P0112** 4. 错词根 → 词组否定；

<a id="p0113"></a>
**P0113** 举例（男士夏威夷衬衫）：

<a id="p0114"></a>
**P0114** • 投 "hawaiian shirts" 广泛 → 搜索后发现 "woman" 相关词得分低（0.4 分） → woman 是错词根 → 词组否 "woman"；

<a id="p0115"></a>
**P0115** • 同样否掉 "kids"、"boy"、"halloween"（特定图案）等；

<a id="p0116"></a>
**P0116** 四、搜索词汇总报表（透视表）

<a id="p0117"></a>
**P0117** 制作方法（两种方式）

<a id="p0118"></a>
**P0118** 方式一：ERP 导出（推荐）

<a id="p0119"></a>
**P0119** 路径（领星 ERP）：广告 → 出单词库 → 筛选产品 → 选择近 30 天 → 导出；

<a id="p0120"></a>
**P0120** 赛狐 ERP 同理，路径找"出单搜索词"页面。

<a id="p0121"></a>
**P0121** 方式二：后台广告报表 + 透视表模板

<a id="p0122"></a>
**P0122** 1. 后台 → 商品推广 → 广告报表 → 下载"搜索词"报表；

<a id="p0123"></a>
**P0123** 2. **选 Daily（每日）格式**，不要选 Summary；

<a id="p0124"></a>
**P0124** • 原因：Daily 可以通过透视表聚合为月/周，但 Summary 无法拆细；

<a id="p0125"></a>
**P0125** 3. 下载最近 **60-65 天**（后台最远支持 65 天）；

<a id="p0126"></a>
**P0126** 4. 打开老师发给大家的透视表模板；

<a id="p0127"></a>
**P0127** 5. 把下载的报表**全选复制**，粘贴到透视表模板的第一个工作表（覆盖原有数据）；

<a id="p0128"></a>
**P0128** 6. 到"透视表"工作表 → 右键刷新；

<a id="p0129"></a>
**P0129** 7. 左边的"加减号"全部折叠；

<a id="p0130"></a>
**P0130** 8. 花费列右键 → 排序 → 降序；

<a id="p0131"></a>
**P0131** 注意：

<a id="p0132"></a>
**P0132** • 后台报表按整个店铺下载，需要在透视表里用"广告组合"筛选出特定产品；

<a id="p0133"></a>
**P0133** • 如果报表表头与模板不一致（亚马逊会更新），可能需要删掉多余列，或联系老师更新模板；

<a id="p0134"></a>
**P0134** • 建议自学 VLOOKUP 和透视表基础（教程已发到群里）；

<a id="p0135"></a>
**P0135** 关于 7 天归因期的处理：

<a id="p0136"></a>
**P0136** • 最近 7 天的数据会变化（订单持续归入）；

<a id="p0137"></a>
**P0137** • 不需要纠结 → 下次导数据时从 7 天前重新开始覆盖即可；

<a id="p0138"></a>
**P0138** 五、推广洞察表：制作与分析

<a id="p0139"></a>
**P0139** （一）制作方法

<a id="p0140"></a>
**P0140** 1. 把准词表**再创建一个副本**，命名为"推广洞察表"；

<a id="p0141"></a>
**P0141** 2. 保留词的基本信息列（搜索量、得分等），**删掉不需要的数据列**；

<a id="p0142"></a>
**P0142** 3. 新增以下列：

<a id="p0143"></a>
**P0143** | 新增列 | 来源 |

<a id="p0144"></a>
**P0144** |---|---|

<a id="p0145"></a>
**P0145** | 广告花费 | 搜索词汇总报表，用 VLOOKUP 导入 |

<a id="p0146"></a>
**P0146** | 广告花费占比 | 透视表中把"花费"改为"总计的百分比"显示方式 |

<a id="p0147"></a>
**P0147** | 广告订单 | 同上 |

<a id="p0148"></a>
**P0148** | 广告 CVR | 同上 |

<a id="p0149"></a>
**P0149** | 广告 CPC | 同上 |

<a id="p0150"></a>
**P0150** | 广告 CPA | 同上 |

<a id="p0151"></a>
**P0151** | 广告订单占比 | 同上 |

<a id="p0152"></a>
**P0152** | 自然位 | 西柚反查自己 ASIN，下载后 VLOOKUP 导入 |

<a id="p0153"></a>
**P0153** 关于自然位的快捷方式：

<a id="p0154"></a>
**P0154** • 西柚反查自己的 ASIN，点"附体（父体）"，下载应用表；

<a id="p0155"></a>
**P0155** • 或者：做准词表时直接把"第一个 ASIN 的自然位"那一列保留下来（H10 数据，非实时但方便参考）；

<a id="p0156"></a>
**P0156** 注意：

<a id="p0157"></a>
**P0157** • 此表适用于已有较多广告花费的老链接；

<a id="p0158"></a>
**P0158** • 新品、花费很少的产品不需要做推广洞察表，分析不出有效信息；

<a id="p0159"></a>
**P0159** （二）分析步骤

<a id="p0160"></a>
**P0160** 第一步：看花费占比

<a id="p0161"></a>
**P0161** • 对比搜索量占比 vs 广告花费占比；

<a id="p0162"></a>
**P0162** • 用"条件格式 → 数据条"分别给两列加颜色，对比是否匹配；

<a id="p0163"></a>
**P0163** • 流量词体量大 → 广告花费也应该多；如果不匹配 → 推广存在盲区或错位；

<a id="p0164"></a>
**P0164** 第二步：判断盈利型 / 投资型广告

<a id="p0165"></a>
**P0165** • 设定定价毛利（如 $8/单）；

<a id="p0166"></a>
**P0166** • 用"条件格式 → 突出显示 → 大于 $8"标红所有 CPA > 毛利的词 → 这些是亏损（投资型广告）；

<a id="p0167"></a>
**P0167** 第三步：盈利型广告的操作

<a id="p0168"></a>
**P0168** 若 CPA < 毛利：

<a id="p0169"></a>
**P0169** • 选项 A：进一步压低 CPA → 对比市调 CPC 范围，判断是否给高了 → 压竞价；

<a id="p0170"></a>
**P0170** • 选项 B：放量 → 在 CPA 不变的前提下扩大花费；

<a id="p0171"></a>
**P0171** • 选项 C：维持现状（如果已没有预算空间）；

<a id="p0172"></a>
**P0172** 举例：

<a id="p0173"></a>
**P0173** • "beach shirts for men"：CPA $6.89，低于毛利 $8 → 盈利型广告；CVR 高、CPC 低 → 可以放量；

<a id="p0174"></a>
**P0174** 第四步：投资型广告的操作

<a id="p0175"></a>
**P0175** 若 CPA > 毛利，先看是否有投资价值：

<a id="p0176"></a>
**P0176** | 判断维度 | 问题 |

<a id="p0177"></a>
**P0177** |---|---|

<a id="p0178"></a>
**P0178** | 搜索量大小 | 这个词够大吗？值得推吗？ |

<a id="p0179"></a>
**P0179** | 当前自然位 | 还有没有上升空间？还是已经卡住了？ |

<a id="p0180"></a>
**P0180** | 预期自然位 | 能推到多高？有没有历史高位证明可以更高？ |

<a id="p0181"></a>
**P0181** | 是否卡在瓶颈位 | 连活动的时候也到不了有效位置？ |

<a id="p0182"></a>
**P0182** 有投资价值 → 写下自然位目标（如目标推到第 10 位），继续亏 2-3 周后复查；

<a id="p0183"></a>
**P0183** 没有投资价值 → 降低 CPA 或缩量；

<a id="p0184"></a>
**P0184** 降 CPA 的优先顺序：

<a id="p0185"></a>
**P0185** 1. 先看 CPC 是否有下压空间（对比市调竞价范围）；

<a id="p0186"></a>
**P0186** 2. 再看 CVR 是否有提升空间；

<a id="p0187"></a>
**P0187** 举例（男士夏威夷衬衫）：

<a id="p0188"></a>
**P0188** • "hawaiian shirts for men"：CPA $12，毛利 $8 → 亏损型；花费是大头（最多）；自然位第 6 → 已经较高，进一步推的空间不大 → 建议缩量或降 CPA；

<a id="p0189"></a>
**P0189** • "hawaiian shirts"：CPA $17，毛利 $8 → 亏损大；自然位 33，历史曾到过前 10 → 有投资价值，但需要分析为什么从前 10 掉到 33；如果能修复，继续投资；否则缩量；

<a id="p0190"></a>
**P0190** 竞价虚高的典型信号：

<a id="p0191"></a>
**P0191** • 同一个词，竞价高的（$2.17）花费多，竞价低的（$1.57/1.16）花费少 → 证明不是竞价低就没效果，而是给高了；

<a id="p0192"></a>
**P0192** • 这说明运营只会靠加竞价放量，而不会其他方法；

**P0214** 七、本节补充：为什么用 Sellics（C服）而不用 H10 建议竞价？

<a id="p0215"></a>
**P0215** 一般情况下推荐用 Sellics（C服） 查竞价，而非 H10 建议竞价。

<a id="p0216"></a>
**P0216** 原因：

<a id="p0217"></a>
**P0217** • H10 抓取的是精准匹配的竞价数据，某些情况下与实际偏低；

<a id="p0218"></a>
**P0218** • Sellics 数据更贴近实际投放竞价，尤其是当你的产品权重较高、竞价已经压得很低时，H10 的参考价值不如 Sellics；

<a id="p0219"></a>
**P0219** • 如果 Sellics 数据也不准 → 建议购买腰部竞品的全店铺广告报表，直接看竞品的实际 CPC；
